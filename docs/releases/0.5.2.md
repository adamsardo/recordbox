# Recordbox 0.5.2

Prepared 2026-11-19 (Europe/Zurich).

Maintenance release from the `fantuz/recordbox` fork, bringing the database,
import-integrity and playback improvements merged since 0.5.1.

## Changes

- Upgrade the bundled database engine to **SQLCipher 4.20.0 / SQLite 3.54.1**
  through `rusqlite 0.42.0`, resolving **RUSTSEC-2026-0459**. Synthetic
  regressions verify encrypted WAL reads, backup/reopen, integrity checks,
  wrong-key rejection and the bundled engine version on every native target.
- Bound PDB page writes after four-byte row alignment and keep row groups
  within their pages. Oversized rows return an error instead of triggering
  the former subtraction panic; aligned-boundary regressions protect the
  row directory from overlap.
- Reuse existing imported audio only when both size and SHA-256 contents
  match. Different same-size files receive a separate destination. Publish
  completed copies from sibling temporary files without overwriting a file
  created at the destination during the import.
- Cache expanded Collection category counts until library metadata changes.
  Rows outside the viewport skip painting/text layout while retaining widget
  identity and keyboard-focus registration. Playback animation remains live.
- Clear the inaudible subnormal tail of smoothed channel/crossfader, trim and
  isolator gains targeting zero. Normal gain values and audible fades retain
  their behavior; the floating-point mode and CPU compatibility are unchanged.
- Add targeted component measurements using generated data on an Intel Xeon
  Platinum 8573C. With 100,000 tracks, warm Artist-category frames fell from
  **275.934 to 74.730 ms**, and all expanded Collection categories from
  **570.498 to 114.116 ms**. A zero-fader callback case covering 20 simulated
  seconds fell from **0.292 to 0.031 s** after warmup. These measurements
  exclude physical devices and whole-window graphics/driver costs; they do
  not establish a reduction in total application CPU. See
  [Playback performance](https://github.com/fantuz/recordbox/blob/v0.5.2/docs/PLAYBACK-PERFORMANCE.md).
- Require a complete, passing serial application suite, removing the former
  PDB failure allowance. The validated baseline is **268 passed, 0 failed,
  36 ignored**, with **107 packaging/release-tooling tests**. Every native
  package runs database/WAL, backup, audio-import and PDB regressions plus
  extracted-application GUI smoke checks.
- Pin local Rust tools to the CI toolchain and document contributor checks,
  opt-in format oracles and a proposed branch ruleset. The ruleset file is
  advisory configuration; merging it does not activate repository protection.
- Reuse all four native packages and matching smoke evidence from one
  successful `main` push for the **exact tag source and VERSION**, avoiding
  a second native build when a complete trusted set is available. Tag runs
  still execute the complete application suite, a fresh advisory audit and
  full archive/source/hash/smoke verification. Missing trusted artifacts
  trigger native builds; artifacts disappearing after selection fail closed.
  See the [release process](https://github.com/fantuz/recordbox/blob/v0.5.2/docs/BUILD-AND-PACKAGING.md#fork-release-process).

## Known limitations

- Two transitive `quick-xml 0.30.0` advisories remain unresolved:
  **RUSTSEC-2026-0194** and **RUSTSEC-2026-0195**. The exact advisory baseline
  is enforced and retained in CI reports; this is not a clean security audit.
- Ignored tests are not executed coverage. Optional format oracles, CPU
  reports and Metal checks have fixture/device requirements. Formatting and
  Clippy findings remain visible but advisory; compilation errors still fail.
- The category workload is a scaling stress case, and the silent-gain case
  does not identify the cause of high CPU with untouched controls. Device,
  display refresh, graphics driver and background analysis costs need their
  own measurements.
- Packages remain **unsigned and not notarized**. Windows/Linux remain
  experimental, with the existing native-menu, device-discovery and
  platform-integration limitations. Metal acceleration remains macOS-specific.
- Synthetic GUI smoke verifies startup/rendering, not physical playback,
  USB hardware operation or Metal computation. Windows smoke uses temporary,
  pinned Mesa DLLs that are excluded from the distributed ZIP.
- This release adds no native STEMS format or universal player/firmware
  compatibility. Unsupported analysis sections retain their existing
  preservation behavior.
