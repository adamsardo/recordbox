# Recordbox 0.7.0

## Save and reuse completed STEMS

Open **Preferences → Extensions → STEMS → Saved stems** and select **Keep all saved stems** to preserve completed separations across track changes and restarts. You can also set a storage budget. The default is 20 GB shared by both models. Each model saves four stereo parts, about 169 MB for a four-minute song. The panel shows the cache folder and any save error. Copy that folder separately when backing up your library. [STEMS storage and backups](https://github.com/fantuz/recordbox/blob/v0.7.0/docs/LIBRARY-SYNC.md#how-much-separation-is-saved)

Export and Performance decks check for saved parts before starting a job, including an early click on **Separate**. One Performance deck can now restore a track while another is separating. Switching between speed and quality restores the matching parts. Cache reads use less memory, and the experimental Linux Vulkan build removes a redundant wait when reading back each transformer projection. [Linux Vulkan guide](https://github.com/fantuz/recordbox/blob/v0.7.0/docs/VULKAN.md)

## Review edits to a desktop Rekordbox library

The sync dialog now offers an explicit write-back direction for supported local desktop libraries. Preview eligible field changes against the imported baseline, review the destination and count, then choose **Back up and apply**. Recordbox checks for conflicts and saves a verified recovery copy before writing. Grid edits include ownership and timing checks for the affected analysis files. Start a write-back trial with a disposable local profile and verify the result in AlphaTheta Rekordbox. [Supported edits and recovery](https://github.com/fantuz/recordbox/blob/v0.7.0/docs/LIBRARY-SYNC.md)

## Review collection cleanup by drive

Right-click **All** under **Collection** and choose **Review collection cleanup…** to inspect missing and duplicate references by drive or volume. Windows and macOS users can select eligible local import references for a backed-up move to Removed Tracks. Records with cloud, external-drive or uncertain origins are protected. Linux provides a read-only report. [Cleanup eligibility and recovery](https://github.com/fantuz/recordbox/blob/v0.7.0/docs/COLLECTION-CLEANUP.md)

Existing lint findings and tracked dependency advisories are listed in the build reports. The release checks require a fresh advisory audit against the repository baseline. [Build checks and known findings](https://github.com/fantuz/recordbox/blob/v0.7.0/docs/BUILD-AND-PACKAGING.md)
