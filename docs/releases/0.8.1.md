# recordbox 0.8.1

This packaging and documentation release adds a Homebrew installation option for macOS and a guide to choosing among the native builds. The detachable library, fullscreen controls and hot-cue fixes shipped in [v0.8.0](https://github.com/fantuz/recordbox/releases/tag/v0.8.0).

## Install with Homebrew on macOS

Install the Xcode Command Line Tools and Homebrew on your Mac, then build and test the app from the fork’s tap.

```sh
brew tap fantuz/recordbox https://github.com/fantuz/recordbox
brew install --build-from-source fantuz/recordbox/recordbox
brew test fantuz/recordbox/recordbox
```

Start the app with `recordbox` in the terminal, or open the bundle with `open "$(brew --prefix fantuz/recordbox/recordbox)/libexec/Recordbox.app"`. The tap builds from a pinned release commit on your Mac and applies a local ad-hoc signature. The macOS ZIP downloads are unsigned and ship without Apple notarization. Use `brew info fantuz/recordbox/recordbox` to see which release the tap currently installs. [Installation and signature details](https://github.com/fantuz/recordbox/blob/v0.8.1/docs/BUILD-AND-PACKAGING.md#homebrew-on-macos)

## Choose a package and find support

The README now covers standard CPU builds on Windows and Linux, macOS Metal support and the optional CUDA, DirectML and Linux Vulkan builds. It also explains which library a sync operation updates and where local STEMS results are saved. The fork focuses on local audio libraries. Dropbox and Google Drive are possible future options for a DJ’s own files. Streaming services are outside this fork’s roadmap. [User guide and upstream credit](https://github.com/fantuz/recordbox/blob/v0.8.1/README.md) · [Report a fork issue](https://github.com/fantuz/recordbox/issues/new)

The build guide documents platform checks, tracked dependency advisories and remaining validation limits. [Build and packaging guide](https://github.com/fantuz/recordbox/blob/v0.8.1/docs/BUILD-AND-PACKAGING.md)
